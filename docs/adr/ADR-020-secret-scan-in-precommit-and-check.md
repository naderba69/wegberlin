# ADR-020: فحص أسرار آلي في خطاف الالتزام وفي بوابة `npm run check`

- **التاريخ:** 2026-09-06
- **الحالة:** مقبول ومُنفَّذ (يبقى البند جزئيًا: المراجعة البشرية لملف الاستثناءات، وفحص التاريخ الكامل في CI)
- **البند:** P0-304 (Secret scan آلي على Git history وpre-commit/CI)

## السياق

المستودع **عام**، والتطبيق يقبل مفتاح OpenRouter اختياريًا من المستخدم ويحفظه في
`sessionStorage` وحده. الخطر العملي ليس في الكود بل في أن ينزلق مفتاح حقيقي — مفتاح
تجريبي، أو نسخة `.env`، أو أثر تصحيح — إلى ملف أو إلى **التاريخ**، حيث لا يكفي
حذف الملف. والاعتماد على الانتباه البشري في مستودع عام ليس ضمانًا.

## القرار

1. **`scripts/secret-scan.mjs`** — مطابقة نمطية عالية الإشارة (9 قواعد: OpenRouter،
   OpenAI، Anthropic، GitHub، AWS، Slack، Google API، مفتاح PEM خاص، وإسناد سرّ
   عام بقيمة ≥16 حرفًا)، مع ثلاثة أنماط تشغيل:
   - `--staged`: محتوى **الفهرس** (ما سيُلتزم فعلًا لا نسخة القرص) — لخطاف الالتزام.
   - `--tree`: كل الملفات المتتبَّعة وغير المتتبَّعة.
   - `--history`: كل التزامات `git rev-list --all`؛ البلاغ مُجمَّع بـ
     (مسار، قاعدة، سطر، الدليل) فلا يتكرر عبر الالتزامات.
2. **استثناءات موثّقة لا صامتة**: `scripts/secret-scan-allowlist.json` يستثني
   (مسار + قاعدة) **بسبب مكتوب**. الاستثناء بالمسار والقاعدة لا بالقيمة، حتى لا
   يتحول إلى ثغرة دائمة؛ ونفس السطر في ملف آخر يبقى بلاغًا.
3. **خطاف التزام بلا تبعية جديدة**: `.githooks/pre-commit` + سكربت `prepare` في
   `package.json` يضبط `core.hooksPath` تلقائيًا بعد `npm install`. لا husky ولا
   تبعية إضافية.
4. **داخل البوابة**: `npm run check` صار يشغّل `npm run secret:scan` (الشجرة
   + التاريخ) قبل البناء — أي أن **CI يفحص الأسرار عبر مهمة `check` القائمة**
   دون تعديل ملف Workflow (وهو ما لا يُسمح للوكيل بفعله، انظر أدناه).
5. **النسخة الضحلة تُبلَّغ ولا تُخفى**: إن كان المستودع ضحلًا (CI يسحب
   `fetch-depth: 1`) يحاول الفحص `git fetch --unshallow origin`؛ فإن نجح فحص
   التاريخ كاملًا، وإن فشل **أعلن أن التاريخ لم يُفحص** بدل ادّعاء السلامة.

## القياس

- الشجرة: **345 ملفًا** — سليم. التاريخ: **8738 ملفًا عبر 28 التزامًا** في ~26 ثانية
  — سليم.
- **7 اختبارات وحدة** جديدة (360/360 إجمالًا): كل قاعدة تُكتشف، والعناصر النائبة
  والتوثيق لا تُبلَّغ، والتعمية تُخفي القيمة وتبقي نوعها، والاستثناء يعمل للمسار
  والقاعدة المحدَّدين فقط، والشجرة الملتزم بها تبقى نظيفة.
- **اختبار اختراق حقيقي**: زُرع مفتاح OpenRouter مزيّف في ملف وصار `git add` ثم
  `git commit` — **الخطاف رفض الالتزام** وطبع المسار والسطر والدليل المعمّى.

## البدائل المرفوضة

- **إضافة مهمة/خطوة Workflow (gitleaks-action وغيرها)**: لا يمكن للوكيل إنشاء ملف
  Workflow أصلًا (توكن التطبيق بلا صلاحية `workflows`)؛ فإدخال الفحص في
  `npm run check` يوصله إلى CI بالفعل عبر المهمة القائمة.
- **husky**: تبعية جديدة مقابل سطر `git config core.hooksPath`.
- **الاعتماد على حظر `.env` بـ`.gitignore` وحده**: لا يمنع مفتاحًا داخل ملف
  مصدر، ولا ينظّف تاريخًا التُزم به قبل الحظر.
- **كشف بالإنتروبيا وحده**: بلاغات كثيرة على سلاسل مشروعة (تجزئات البناء،
  معرّفات المحتوى)، وفائدة قليلة فوق القواعد العالية الإشارة.

## الحدود المعلنة

- مطابقة نمطية: لا تدّعي كشف كل سر ممكن، ولا تفحص محتوىً مشفّرًا أو ملفات ثنائية
  (تتجاوز ما يظهر منه محتوى ثنائي أو ما زاد على 1 MiB).
- ملف الاستثناءات **قرار بشري**: كل إضافة فيه تُضعف البوابة ويجب أن تُقرأ.
- في CI: فحص التاريخ مكتمل **إن نجح** `git fetch --unshallow`؛ وإلا يُعلن الفحص
  صراحة أن التاريخ لم يُفحص. ولا وجود لمسح دوري مجدول على التاريخ — فحص التاريخ
  هنا عند كل تشغيل للبوابة، لا مهمة ليلية.
