# ADR-075 — Phoneme reference layer and gated remote correction, both without readiness claims

- **Status:** accepted and implemented as code plus automated tests; readiness flags remain closed
- **Date:** 2026-09-13
- **Scope:** `src/core/german/*` (phoneme inventory, reference, alignment, policy), `src/core/writing/german-grammar-signals.ts`, `src/core/ai/writing-review-gate.ts`, `src/core/speaking/review-lanes.ts`, the three new panels, persistence of transcript confirmation

## Context

Two learner requests pull in opposite directions. Learners want per-sound pronunciation feedback and free writing/conversation correction. The repo can currently prove neither to the standard this project sets for itself:

1. Pronunciation surfaces prove **word matching** from the local Whisper model. That is an ASR result, not a phoneme measurement. The candidate acoustic model (`pklumpp/Wav2Vec2_CommonPhone`, 101 IPA symbols, reported German PER 9.8, CC0) is a Hugging Face PyTorch checkpoint; there is no pinned revision, no ONNX/q8 artefact, no Web Worker run, no memory/heat/latency measurement on a phone, no accept-threshold calibration, and no German-native or Arabic-learner trial. A separate forced aligner (Bournemouth) is Python/PyTorch, so it is not a browser runtime.
2. Free writing correction was one lane: local deterministic patterns, plus optional Gemini. The learner asked that Gemini act as a consultant for what the local engine cannot settle, with real quoting, an Arabic explanation, a German rule, a remediation drill, and a human-review flag — and that a spoken answer never be judged on text Whisper misheard.

A rule-based grapheme-to-phoneme transducer was built and measured during this work: 35 of 53 curriculum words matched the human-authored IPA (failures: `ou`→`oː`, geminate `-ig/-chen`, lexical vowel length, `n̩`, initial-only `sp/st`→`ʃ`, coda `r` as `ʁ` vs `ɐ`). That is not good enough to present as "the German sound", so the transducer was deleted rather than shipped with a caveat.

## Decision

1. **Phoneme layer shows authored references only.** `src/core/german/phoneme-reference.ts` (`german-phoneme-reference-v1`) builds a lexicon from the human-authored Arabic-learner contrast inventory and from the `pronunciation.items` each lesson page already owns, and it refuses to answer for a word the curriculum has not authored. Where one spelling carries two authored readings (`UMfahren` / `umFAHren`), both are kept as variants; neither silently shadows the other.
2. **Alignment exists as an engine, not as a claim.** `phoneme-alignment.ts` (`german-phoneme-alignment-v1`) implements Needleman–Wunsch alignment over `splitIpaIntoPhonemes` tokens, deletion/insertion/substitution classes, vowel length as a first-class contrast, accepted r-variants (`ʁ`/`ʀ`/`r`, `ɐ̯`) as non-errors, and the three required states: confirmed / needs-retry / technical-unverifiable. A sentence passes only when every word passes **in the same attempt** (`sameAttempt` is part of the result); a missing or unconfirmed observation is never a pronunciation error. There is no averaged phoneme score — `compositeScore` is `null` by type.
3. **Readiness is a ledger, not a vibe.** `phoneme-policy.ts` (`phoneme-observation-policy-v1`) keeps `phonemeAssessment`, `perPhonemeFeedback`, `accentScore`, `fluencyScore`, `officialExamPronunciationScore` at `false`, lists nine evidence steps with `evidence: null`, and refuses any generated text containing claim-shaped fragments ("لهجتك"، "طلاقتك"، "نطق سليم"، "Pronunciation score", `x/100`). Providers are a port with exactly one implementation today: local word matching, `phonemeGradeable: false`.
4. **The local checker is the primary writing teacher.** `german-grammar-signals.ts` (`german-grammar-signals-v1`) adds nine deterministic rules over word order, case government of `mit/für/…`, capitalization, `dass`/`das`, comma placement and separable prefixes, each producing a verbatim excerpt, a German restatement, an Arabic explanation, and the source of the rule. Two certainty levels exist: `proven` (spelling plus the authored lexicon decides it) and `probable`. Anything the engine will not decide goes to a visible `unresolved` channel instead of being guessed. Measured on the authored corpus: 9 of 9 learner sentences, 0 `proven` false positives over 84 model answers, and the whole scan under 100 ms in this sandbox.
5. **Gemini is a gated consultant.** `writing-review-gate.ts` rejects an answer whose excerpt is not literally in the approved text, a suggestion that rewrites the whole text (≥85 % token overlap and length), any official score/grade/pass/CEFR/100 %-correct claim in **either the issues or the summary**, more than one exam brand in the same answer, and self-contradictory certainty. A single brand is not a rejection but is labelled as general information. Anything missing a rule or a drill for a high-confidence finding becomes `needsHumanReview`. `acceptedIssues`/`assertWritingReviewGrounded` are the only ways to store or surface an issue.
6. **Speech is confirmed before it travels.** `review-lanes.ts` (`speaking-review-lanes-v1` / `speaking-confirmed-transcript-v1`) records a transcript draft from local ASR, requires an explicit learner confirmation (minimum three German words), detects edits made after confirming (`isTranscriptStale`), and refuses the send if the text changed. `speaking-lab.tsx` applies the check before opening the consent dialog and keeps the remote button disabled while confirmation is outstanding. Audio never enters the request.
7. **Three lanes, never one number.** Acoustic, linguistic and task-fulfilment results are separate objects, each with its own `canClaimScore: false` and boundary string, rendered as three sections. Persistence stores only the learner's transcript confirmation evidence (`SpeakingTranscriptConfirmation`); lane snapshots are page state. New optional fields (`ruleDe`, `remediationAr`, `needsHumanReview`, `needsHumanReview` on evidence, `transcriptConfirmation`) are `.optional()` everywhere, so v1 export records still validate.

## Boundary

This batch is code and automated proof. The phoneme engine is **not** enabled: no pinned model revision, no ONNX/q8 artefact, no device measurement, no calibration, no German-native or Arabic-learner trial, no independent phonetic review. The remote correction path is code-complete and tested, but free-tier availability is not ours to guarantee and there is no paid fallback. Nothing here certifies an accent, a level, an exam format, or a text as error-free; the wording the learner sees says "within engine limits" for that reason.
