## 11 · العطل الحقيقي: «This page couldn't load» لكلِّ متعلّمٍ أتمَّ ٨ دروس

بعد إصلاحِ النشر ظلَّ المالكُ يرى **«This page couldn't load. Reload to try again, or go back»**
رغم تبديلِ المتصفَّحِ ومسحِ الكاش. وكان `curl` يردُّ **200** على كلِّ المسارات، فبدا الموقعُ سليمًا؛
والسببُ أنَّ `curl` لا يُنفِّذ JavaScript. فشُغِّل متصفِّحٌ حقيقيٌّ (Playwright) على الموقع الحيِّ:
الصفحةُ الرئيسيةُ سليمةٌ بلا أخطاء. إذًا العطلُ مشروطٌ بحالةِ المتعلِّمِ لا بالنشر.

**إعادةُ الإنتاج:** كُتِبت حالةُ تعلُّمٍ حقيقيَّةٌ في IndexedDB ثمَّ أُعيد التحميل. النتيجة:

```
✓ 7 دروس مكتملة   → سليم
💥 8 دروس مكتملة  → انهيار كلّ الصفحات
```

والخطأُ في الطرفية: `Minified React error #185` أي **Maximum update depth exceeded**.

**السبب الجذري:** في `src/components/device-value.ts`

```ts
useDeviceValue(() => Date.now(), 0)   // ← يُمرَّر إلى useSyncExternalStore
```

و`useSyncExternalStore` يستدعي `read()` بعد كلِّ رسمٍ ويقارنُ النتيجةَ **بالمرجع**؛ و`Date.now()`
يعودُ بقيمةٍ جديدةٍ في كلِّ استدعاء، فلا يستقرُّ الرسمُ أبدًا ⇒ حلقةٌ لا نهائيَّة. ولم يظهر العطلُ
للزائرِ الجديد لأنَّ `buildDueReviewQueue` لا يُنتِج مراجعاتٍ مستحقَّةً إلَّا بعد تراكمِ تقدُّمٍ
حقيقيّ، وعندها فقط يُفعِّل `ReviewReminderCoordinator` المسارَ الحسَّاس. أي أنَّ **العطلَ كان يُصيب
المتعلِّمَ الجادَّ وحدَه** — وهو أسوأُ أنواعِ الأعطال: الموقعُ يبدو سليمًا في كلِّ فحصٍ سطحيّ.

**كيف عُزِل:** حُذِف كلُّ مكوِّنٍ عامٍّ من القشرةِ على حِدَة وأُعيد البناءُ والاختبار:

**`ReviewReminderCoordinator` ⇒ توقَّف الانهيارُ وظهرت المقالاتُ الأربع.** ومنه إلى `useDeviceValue`.

**العلاج:** `useDeviceEpoch` يثبِّت اللحظةَ **مرَّةً واحدةً** على مستوى الوحدة بعد الترطيب، وحُوِّلت

`study-export-control.tsx`. الشاشاتُ التي تحتاج ساعةً حيَّةً تملك مؤقِّتها الخاصَّ (`setInterval`).
